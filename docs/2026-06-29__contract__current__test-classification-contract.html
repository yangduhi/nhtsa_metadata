3. Source of truth 우선순위#

분류 판단은 단일 컬럼으로 결정하지 않는다. 아래 순서와 원칙을 함께 적용한다.

우선순위Source계약상 의미
1원본/source payload, raw row JSON, endpoint row hash재현 가능한 provenance. 수정 대상이 아니라 보존 대상.
2local canonical DB row: tests, barriers, test_participants, vehicles, test_classification현재 운영 DB의 구조화된 local source. 단독 판단 금지.
3auxiliary evidence: 특히 barriers.raw_row_json의 BARCOM, BARRIGD, BARSHPD, BARANGheadline config/title을 보정하거나 hidden evidence를 제공.
4official external evidence: eCFR 49 CFR Parts 571/575/581, NHTSA official pages, static EV package TEST line, official report PDFtaxonomy anchor와 confidence 부여의 핵심 근거.
5live NHTSA endpoint최신 확인에 유용하지만, endpoint가 누락되어도 static EV/report/local evidence가 있으면 row invalid로 보지 않는다.
6high-confidence inferred ruletitle/config/speed/barrier/source가 일관될 때만 overlay 후보. 물리 conflict는 review.

계약상 금지: test_configuration_key 하나만으로 family를 결정하지 않는다.

4.3 물리적 정확성 우선#

분류와 scalar metadata fill은 물리 의미가 우선이다.

  • EV5 TEST.IMPANG=0이 side-impact row에서 나와도, side-pole/side-MDB 물리 방향을 0도로 덮어쓰지 않는다.
  • ADAS/TJA CSV trajectory velocity는 scenario evidence이지 crash scalar closing_speed가 아니다.
  • has_video는 record-present 의미이며 media URL usable 보장이 아니다.
  • /vehdb video URL은 nrd-static HTTPS로 normalize하고 필요한 경우 percent-encoding한다.
  • graph/window 분석에서는 이미 승인된 물리 window 정의를 유지한다.

7. Family별 분류 기준#

7.1 Frontal fixed barrier#

대표 anchor:

  • NHTSA NCAP frontal fixed barrier: 35 mph / 약 56 km/h fixed barrier.
  • FMVSS 208 frontal fixed rigid barrier.
  • FMVSS 301 frontal/fuel integrity context는 frontal fixed physical condition으로 분리 기록.

주요 기준:

  • VTB + frontal/fixed barrier title/config/speed/barrier evidence.
  • load-cell wall/barrier evidence는 frontal fixed barrier 안의 instrumentation/face evidence로 기록하며 별도 family로 빼지 않는다.
  • barriers.raw_row_json.BARCOM이 FLAT BARRIER, FLAT WALL, LCB, LOAD CELL 등을 제공하면 headline UNKNOWN/OTHER shape보다 우선한다.

FMVSS208 VTB four-mode split:

FMVSS208_S17_S18_40PCT_OFFSET_DEFORMABLE_BARRIER339.3–39.8 kph, DEFORMABLE / EEVC OFFSET BARRIER, BARCOM=40% ODB
FMVSS208_S5_S16_40K_UNBELTED_FIXED_RIGID_BARRIER6939.1–39.9 kph, RIGID / FLAT BARRIER, angle 0

7.2 Side MDB#

대표 anchor:

  • NHTSA NCAP side moving barrier: 38.5 mph side barrier.
  • FMVSS 214 side MDB.

주요 기준:

  • side impact / moving deformable barrier / MDB / ITV + side-title/config/barrier evidence.
  • load-cell barrier row가 있더라도 side moving barrier instrumentation/face evidence로 기록하고 family는 SIDE_MDB로 유지한다.
  • EV5 IMPANG=0이 있어도 physical side-MDB impact angle로 자동 fill하지 않는다.

7.3 Side pole#

대표 anchor:

  • NHTSA NCAP side pole: 75° / 20 mph rigid pole.
  • FMVSS 214 fixed rigid pole 254 mm, up to 32 km/h.

주요 기준:

  • VTP, SIDE POLE, RIGID POLE SIDE, VEHICLE-TO-POLE, POLE IMPACT title/config/evidence.
  • keyword trap 방지: “75 DEGREE OBLIQUE RIGID POLE SIDE NCAP IMPACT”는 frontal oblique가 아니라 side pole이다.
  • VTB로 miscoded된 FMVSS214 pole 8건은 official title/package가 config를 보정하므로 SIDE_POLE_FMVSS214_MISCoded_VTB로 유지한다.
  • barrier row가 없어도 VTP/title/speed가 명확하면 family를 뒤집지 않고 source-completeness review flag를 붙인다.

7.4 Child restraint#

대표 anchor:

  • FMVSS 213 / 213a / 213b.
  • NHTSA static EV package TEST line.

주요 기준:

  • FMVSS 213, CRABI, booster, child seat, CRS, LATCH, child restraint title/config.
  • DOT_SIDE_* 57건은 EV package가 child restraint deceleration sled study를 직접 명시하므로 generic sled가 아니라 CHILD_RESTRAINT.
  • T62FRONT_* FMVSS NO. 213 41건은 child restraint frontal/research sled로 분류.

7.5 Airbag deployment / static OOP#

대표 anchor:

  • FMVSS 208 occupant protection / NHTSA air bag program context.

주요 기준:

  • LRD 261건은 low-risk/static deployment로, frontal crash-wall 4-mode 밖에 둔다.
  • static side airbag/OOP row는 barrier UNKNOWN/RIGID가 있어도 BARCOM=NO BARRIER이면 explicit no-barrier airbag test다.
  • pole fixture가 있어도 static side-airbag OOP fixture일 수 있으므로 side-pole crash로 오분류하지 않는다.

7.6 Pedestrian#

대표 anchor:

  • NHTSA static EV package TEST lines.
  • pedestrian headform / upper legform / lower legform / certification contexts.

주요 기준:

  • PED config/family, headform/legform title/config.
  • null impact_angle은 vehicle crash angle이 not-applicable일 수 있으므로 무리하게 0도로 채우지 않는다.

7.8 EJM / FMVSS 226 ejection mitigation#

  • FMVSS 226 Ejection Mitigation은 test_configuration_key=EJM을 사용한다.
  • vehicle crash가 아닌 ejection impactor/window mitigation 성격이므로 frontal/side crash family로 밀어 넣지 않는다.

7.9 ADAS FCW / LDW / TJA#

  • FCW/LDW는 NHTSA ADAS/ratings context와 package evidence로 분류한다.
  • TJA 1건은 official protocol 근거가 부족하므로 ADAS_TJA family에 두되 official_insufficient 또는 scenario evidence flag를 유지한다.
  • TJA CSV trajectory speed는 scenario evidence로 저장하며 crash scalar closing_speed로 승격하지 않는다.

7.10 Rollover / rear impact / bumper / interior-seat research / sled research#

  • Rollover는 NHTSA rollover/SSF context와 rollover fixture evidence를 보존한다.
  • Rear impact는 FMVSS301 또는 rear-impact title/config/evidence로 분류한다.
  • Bumper damageability는 49 CFR Part 581 anchor를 사용한다.
  • Interior fitting / seat research는 FMH/interior/seat/rear-seat research context를 family와 research flag로 함께 표현한다.
  • Generic sled는 child restraint/OMDB/full-vehicle crash와 분리한다.

12. Interview register — 사용자 의도 확인 필요#

아래 질문은 계약의 최종 권한과 운영 방식에 영향을 주며, 사용자는 권장안을 승인했다. 향후 같은 수준의 의도 판단이 필요한 경우 항상 질문한다.

Q1. 문서 권한 수준#

왜 필요한가: 이 문서가 단순 요약인지, 앞으로 DB/API/GUI 작업을 구속하는 기준인지가 다르다.

Option의미장점단점Recommendation
Acurrent 운영 계약으로 승격향후 작업 기준이 명확사용자 검토 후 정교화 필요권장
Bdraft 참고 문서로 유지빠르게 참고 가능후속 작업에서 기준 충돌 가능
Cphase report로만 저장회고/기록에 적합계약/acceptance gate 역할 약함

기본 추천: A. 이미 DB/API/GUI final overlay가 실제 연결되어 있으므로 운영 기준 문서가 필요하다.

Q2. UI/API 기본 분류 축#

왜 필요한가: 사용자 화면에서 broad family만 보여주면 단순하지만, 규정 mode와 evidence를 잃을 수 있다.

Option의미장점단점Recommendation
Afamily/category/mode 3계층 모두 노출가장 정확하고 trace 가능UI가 복잡해질 수 있음권장
Bfamily 중심, detail에서만 mode 표시메인 UI 단순mode 기반 필터가 약해짐
Cmode 중심으로 전면 노출규정/물리 분석에 강함일반 사용자에게 어려움

기본 추천: A. 상위 facet은 family, drilldown/filter는 category/mode를 제공한다.

Q3. Manual-review/source-completeness flag row의 기본 포함 여부#

왜 필요한가: review flag가 있다고 해서 분류를 제외하면 denominator와 실제 사용성이 깨질 수 있다.

Option의미장점단점Recommendation
A기본 포함 + flag 표시denominator 보존, 사용성 높음사용자가 flag 의미를 이해해야 함권장
B기본 제외 + opt-in보수적 분석 가능counts/facets가 denominator와 달라짐
C위험도별 partial include균형 가능정책 복잡도 증가

기본 추천: A. category reversal이 아닌 source-completeness flag는 포함하되, evidence flag로 명확히 노출한다.
